# CPX 构建与部署使用指南

本文档介绍 CPX 项目的自动化部署流程、涉及的脚本及关键命令，推荐先阅读“快速一键部署”再根据需要了解手动操作方式。

---

## 1. 快速一键部署（推荐）

根目录提供 `install.sh` 用于自动完成以下操作：

1. **检查并安装 Docker / Docker Compose**
   - 若缺失，调用 `scripts/install_docker_git.sh` 拉取最新版 Docker（含 compose 插件），并提示/设置数据目录。
2. **生成所需配置**
   - 缺少 `runner-compose.yml`、`redis_cache/redis.conf`、`redis_market/redis.conf` 时自动执行 `scripts/generate_runner_passwords.sh`，基于 `*.temp` 模板替换 `{*_password}`。
   - 缺少 `nginx/conf.d/cpx_exchange.conf` 时自动调用 `scripts/configure_nginx_domains.sh`，交互式收集主域名及二级域名前缀，将模板 `cpx_exchange.temp.conf` 渲染为正式配置。
3. **初始化数据卷**
   - 创建/授权 Redis、Elasticsearch、MySQL、Nginx 日志等目录（含 UID=1000 的 ES 数据目录）。
4. **启动核心容器**
   - 使用已检测到的 `docker compose` 或 `docker-compose` 执行 `runner-compose.yml`，最后输出查看状态/日志的命令。

**使用方式：**

```bash
chmod +x install.sh
./install.sh
```

脚本执行过程中如需输入信息（例如 Docker 数据目录、Nginx 域名），请按提示完成交互，脚本会自动继续后续步骤。

## 2. 配置生成脚本说明

### 2.1 Docker & Compose 安装脚本
- **路径**：`scripts/install_docker_git.sh`
- **作用**：在 Linux/macOS 上自动安装最新稳定版 Docker 与 Compose（默认 v2.29.2，可通过 `DOCKER_COMPOSE_VERSION` 自定义），并在 Linux 上询问 Docker 数据目录写入 `/etc/docker/daemon.json`。
- **调用方式**：`bash scripts/install_docker_git.sh`

### 2.2 核心服务配置脚本
- **路径**：`scripts/generate_runner_passwords.sh`
- **作用**：读取 `runner-compose.temp.yml`（可通过 `RUNNER_COMPOSE_TEMPLATE` 重定向），生成随机密码替换所有 `{*_password}`，并将结果分别写入 `runner-compose.yml`、`redis_cache/redis.conf`、`redis_market/redis.conf`（或脚本参数指定的其他模板文件）。
- **输出**：终端打印每个占位符对应的随机密码供记录。
- **调用方式**：`scripts/generate_runner_passwords.sh`（可附加模板路径参数）。

### 2.3 Nginx 域名配置脚本
- **路径**：`scripts/configure_nginx_domains.sh`
- **作用**：基于 `nginx/conf.d/cpx_exchange.temp.conf` 交互式生成 `cpx_exchange.conf`。脚本先询问主域名，再依次询问 API/管理端/H5/APP 的子域名前缀（默认 `api/manager/h5/app`，可直接回车使用默认），最终替换 `{api_domain}`、`{manager_domain}` 等占位符。
- **调用方式**：`scripts/configure_nginx_domains.sh`（可用 `NGINX_TEMPLATE`、`NGINX_OUTPUT` 环境变量覆盖输入/输出路径）。

## 3. 手动部署或排障参考

如需自行控制流程，可按以下步骤手动执行（假设 Docker/Compose 已安装且配置文件已生成）：

### 3.1 启动核心服务

```bash
docker compose -f runner-compose.yml up -d
docker compose -f runner-compose.yml logs -f   # 查看启动日志
```

确保各容器状态为 `Up`，再继续下一步。

### 3.2 部署链上钱包（可选）

```bash
bash scripts/setup_cpx_wallet.sh
```

该脚本会自动拉取代码并启动钱包相关容器。

### 3.3 配置域名解析

为脚本生成的域名（默认 `api.* / manager.* / h5.* / app.*`）添加 DNS 记录或写入 `hosts`，全部指向部署服务器的公网 IP。

### 3.4 启动 Nginx 反向代理

```bash
cd nginx
docker compose up -d
docker compose logs -f   # 可选：查看代理日志
```

修改 `nginx/conf.d/cpx_exchange.conf` 后再次执行 `docker compose up -d` 即可热更新。

## 4. 镜像升级与维护

以后台管理端 `cpx_manager` 为例：

```bash
docker compose -f runner-compose.yml pull cpx_manager
docker compose -f runner-compose.yml up -d cpx_manager
# 如需强制重建，附加 --force-recreate
# docker compose -f runner-compose.yml up -d --force-recreate cpx_manager
docker image prune   # 可选：清理旧镜像
```

其他服务可按同样方式替换服务名执行。

## 5. 常见问题

- **脚本提示缺少模板文件**：确认 `runner-compose.temp.yml`、`redis_*/redis.temp.conf`、`nginx/conf.d/cpx_exchange.temp.conf` 存在于仓库根目录及对应子目录。
- **Docker 数据目录无写权限**：以 root 或具有 sudo 权限的用户执行 `install.sh`，脚本会自动创建目录并赋权；若仍失败可手动调整权限后重试。
- **需要重新生成密码/域名**：删除目标配置文件后重新运行 `scripts/generate_runner_passwords.sh` 或 `scripts/configure_nginx_domains.sh`，再执行 `install.sh` 或 `docker compose up -d`。
